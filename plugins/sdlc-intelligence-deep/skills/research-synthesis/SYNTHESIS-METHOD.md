# Research Synthesis Method

Use this reference when synthesis requires more than a small coherent observation-to-finding pass. Select analytical structure from the research question and corpus topology; do not apply every section mechanically.

## 1. Choose the analytical shape

| Evidence/question shape | Prefer | Why | Warning sign |
|---|---|---|---|
| Small coherent research round; same population/method; concrete question | Lightweight pattern synthesis | Low ceremony while preserving observation -> pattern -> finding | You are inventing a large codebook/matrix that cannot change the conclusion |
| Comparable participants/cases/segments/tasks; need similarities and differences | Case-by-dimension / framework matrix | Preserves within-case context before cross-case comparison | You aggregate excerpts globally and lose why a pattern differs by case |
| Exploratory meaning/pattern question; boundaries are not known in advance | Iterative code/theme development | Lets analytical concepts evolve from engagement with the corpus | Topic folders or frequent words are promoted directly to "themes" |
| Qualitative + quantitative or heterogeneous evidence answer related parts of a question | Mixed-evidence integration | Forces explicit alignment and an integration inference | Sources are vote-counted or one modality automatically outranks the other |
| Different evidence groups answer materially different questions | Parallel findings with explicit relation | Avoids false convergence/conflict | You force incomparable evidence into one synthesized score |

A project may combine shapes. For example, compare interview cases in a matrix, then integrate the bounded qualitative finding with segment-specific analytics.

## 2. Set the unit before comparison

Write down the unit of analysis that controls the claim. Common units include:

- participant/account/case;
- task or workflow episode;
- event or incident;
- segment/cohort;
- research session or source;
- metric/time period;
- product area or decision context.

Do not silently switch units. A participant statement about difficulty and an aggregate completion rate can both be true because one describes experienced difficulty and the other describes eventual task completion.

When the unit changes, state the inference connecting the levels instead of treating them as direct confirmation.

## 3. Build an analytical framework without turning it into a filing system

For each material code/category, keep enough meaning to distinguish it:

```text
label
meaning / central idea
include when
exclude when
examples or source refs
known overlaps / competing interpretations
```

Use initial/open codes when the question is exploratory. Introduce a more stable framework only after repeated use shows that the distinctions help answer the question.

Revise the framework when:

- examples fit multiple codes for the same reason;
- one code mixes distinct mechanisms/contexts;
- a code is only a document heading or product area;
- a code remains "thin" and contributes no distinct finding;
- new evidence exposes a missing distinction.

Do not use code frequency as a proxy for importance. Frequency may describe prevalence only when sampling/collection semantics support that inference.

## 4. Compare within cases before collapsing across cases

When the corpus has comparable cases/segments, first preserve each material case's context:

```text
case/segment x analytical dimension -> observation summary + source refs + contradictions
```

Then compare across cases for:

- recurring pattern;
- meaningful variation;
- boundary condition;
- sequence or dependency;
- segment-specific mechanism;
- absence where the pattern would have been expected.

A cross-case finding must explain both where it holds and the material conditions under which it does not.

## 5. Pressure findings with negative/deviant cases

For each candidate finding, ask:

1. What evidence most strongly supports it?
2. What evidence would make it false, narrower, or different?
3. Is there a case where the expected pattern does not appear?
4. Does the contrary case reveal another segment, context, mechanism, or timing condition?
5. Is a rare case low-frequency but high-consequence?

Respond by changing the finding, not by hiding the case:

- **narrow** the population/context;
- **split** one finding into different mechanisms;
- **qualify** the condition under which it holds;
- **retract** it if the interpretation is no longer supported;
- **retain as an edge/risk finding** when rare evidence has material consequence but limited prevalence support.

## 6. Triangulate by evidence relationship, not source count

Before claiming corroboration, inspect how evidence was generated.

Treat sources as dependent when they share material lineage such as:

- the same participants or sample;
- the same survey/interview dataset summarized in several documents;
- one report copying another;
- dashboards derived from the same underlying instrument/pipeline;
- one analyst's interpretation reused as "source" by later artifacts.

For each relation, classify the evidence as one of:

- **reinforces** — aligned construct/unit/population/time and independently generated evidence supports the same bounded finding;
- **explains** — one source helps explain a pattern seen in another;
- **qualifies** — one source narrows the conditions/scope of another;
- **conflicts** — aligned evidence supports materially incompatible interpretations;
- **not comparable** — different construct/unit/population/time prevents a direct convergence claim;
- **dependent** — apparent multiple sources share one evidence-generation lineage.

Do not count these categories numerically to manufacture confidence.

## 7. Integrate qualitative and quantitative evidence intentionally

Before integration, align:

- construct/question being measured or described;
- population/segment and eligibility;
- analysis unit;
- period and maturity window;
- directness to the target question;
- data-generating/selection mechanism.

Use a simple claim-by-evidence joint comparison when helpful:

```text
candidate finding | qualitative evidence | quantitative evidence | fit/relationship | boundary/next question
```

Possible fit includes confirmation, expansion, explanation, qualification, true conflict, and non-comparability.

Do not make quantitative evidence the winner merely because `n` is larger. Do not turn qualitative evidence into pseudo-statistics merely to compare modalities.

## 8. Treat analyst interpretation as part of the analytical system

When interpretation is material:

- state the working interpretation and plausible alternative;
- identify which source context or concept definition differentiates them;
- record assumptions introduced by the analyst;
- seek discriminating evidence when the difference changes the decision;
- involve a qualified research/domain owner when specialized interpretation or high-consequence judgment exceeds the current analyst's authority.

Do not treat inter-analyst majority vote as truth. If the project explicitly uses a codebook/reliability protocol, follow that method's own rules; do not mix it silently with reflexive interpretation assumptions.

## 9. Construct a falsifiable finding

A useful finding contains:

```text
claim / pattern
scope: who/where/when/under what condition
supporting evidence
negative/conflicting evidence
source-dependency note
interpretive alternatives when material
confidence rationale
transferability boundary
limitations
implications (not approved decisions)
```

Reject or revise a candidate finding when:

- it is only a topic/category label;
- its scope is broader than represented evidence;
- it survives only by ignoring negative cases;
- it claims prevalence the sampling method cannot support;
- it claims causality the evidence design cannot support;
- its apparent corroboration comes from dependent sources;
- its implication is doing the work of the finding itself.

## 10. Confidence is not transferability

Judge confidence in the bounded finding using only material lenses:

- quality/methodological limitations of contributing evidence;
- relevance/directness to the research question;
- adequacy/richness and coverage for the claimed boundary;
- coherence between evidence and the finding, including contrary cases;
- source independence/dependency and selection effects;
- recency when the phenomenon can change.

Then make a separate transferability statement: what populations, contexts, workflows, or periods are represented, and where applicability is unknown.

Do not claim formal GRADE-CERQual assessment unless the task is actually performing that method. The lenses above are adapted as general reasoning prompts, not a certification label.

## 11. Earliest-failure re-entry

| Failure discovered | Re-enter at | Correction |
|---|---|---|
| Quote/event was extracted out of context | extraction | correct the evidence unit, then invalidate dependent codes/findings |
| Code boundaries overlap or do not discriminate examples | analytical framework | redefine/split/merge codes and re-check affected cases |
| Negative case contradicts the candidate pattern | finding boundary | narrow/split/qualify/retract; do not only lower confidence |
| Cross-case pattern disappears when cases are examined separately | within-case comparison | restore case context and rebuild the cross-case inference |
| Mixed evidence used different unit/population/time/construct | integration frame | align the comparison or mark not comparable |
| "Three sources" are derivatives of one evidence pipeline | evidence lineage | collapse the independence claim and revise confidence |
| Analyst interpretations diverge on a decision-material point | interpretation frame | inspect definitions/context, seek discriminating evidence, or escalate |
| Product/design recommendation exceeds evidence | finding/implication boundary | restate the evidence-grounded implication and return the decision to its owner |

Stop when re-analysis cannot change a material finding/decision, or when the next uncertainty requires new evidence owned by `research`.
