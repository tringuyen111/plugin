# Priority Decision

Use this module when **priority or Product disposition depends on uncertain or competing factors**. A scoring framework may support judgment but must not manufacture inputs or authority.

Consider only evidence-backed factors material to the current decision:

- expected user/business value and the mechanism by which the capability changes a condition;
- evidence confidence and transferability;
- urgency/time sensitivity when real;
- strategic alignment;
- estimated learning/delivery cost when available;
- risk and reversibility when material;
- opportunity cost: what moves, waits, or remains uncommitted.

RICE, ICE, MoSCoW, value/effort, or another framework is optional support. Do not treat a completed score as authority. Never invent reach, impact, confidence, effort, market size, or weights.

When uncertain inputs/weights could change the ordering, expose sensitivity:

```text
current priority rationale
        -> uncertain input / weight
        -> plausible range / qualitative alternative
        -> does the decision change?
        -> exact evidence / authorized owner input needed if decision-critical
```

If alternatives swap under plausible assumptions, preserve a conditional/tied disposition rather than hiding sensitivity behind a point score.

## Failure / correction

- guessed score presented as decision truth -> remove fake precision and return qualitative evidence-backed trade-off/sensitivity.
- usage frequency substitutes for value -> return to value mechanism/current consequence.
- portfolio priority is invented to park/reject -> preserve Product-level rationale and expose missing portfolio authority.
- priority change depends on one unauthorized weight -> return the exact owner input/evidence need instead of choosing it.

## Return contract

Return only:

```text
priority rationale / disposition
material evidence-backed factors
uncertainty + sensitivity
opportunity cost
exact evidence or authorized input that would change the decision
```
