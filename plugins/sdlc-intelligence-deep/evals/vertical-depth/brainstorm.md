# Brainstorm standalone / anti-fixation qualification cases

Status: `NOT_RUN` until executed against an actual model/runtime. Baseline was frozen before Brainstorm source mutation at exact Plugin `sdlc-intelligence-deep v1.0.27`, SHA-256 `233c9ba86928ebfe33d3be73b6d9557b07359131a34b9675bc50f0a096df862e`.

The changed claim is not "more complete documentation." It is: Brainstorm independently improves raw/fuzzy idea quality through proportional divergence, semantic deepening, discrimination, and convergence without requiring sibling Skills or a Markdown/file lifecycle.

## Representative cases

1. **Explicit raw-idea brainstorm**
   - Input: `/brainstorm add collaborative review spaces to our dashboard product`.
   - Expected: bind known truth, expose the open exploration frontier, explore/deepen proportionally, and reach useful pre-canonical idea state without another Skill.
   - Falsifier: immediately routing to Product/Requirements/Design or requiring a sibling to continue.

2. **Semantic implicit trigger**
   - Input: `I have a rough idea for shared workspaces; help me think it through.`
   - Expected: Brainstorm is eligible even though its name was not invoked; metadata and method agree.
   - Falsifier: description says explicit-only or runtime metadata disables/contradicts the intended trigger.

3. **Fixed downstream work is a non-trigger**
   - Input: `Implement the approved retry policy in this API client.`
   - Expected: do not broaden into raw-idea Brainstorm merely because implementation contains choices.
   - Falsifier: Brainstorm becomes a mandatory pre-step for ordinary fixed downstream work.

4. **Evidence question near-miss**
   - Input: `Do users actually have a problem with our onboarding?`
   - Expected: do not fabricate user evidence; identify evidence/opportunity research as the missing owner/evidence class if current facts cannot answer.
   - Falsifier: brainstorm hypotheses are presented as customer validation.

5. **Standalone runtime**
   - Input: Brainstorm is the only installed Skill; user supplies a raw idea with enough context to explore.
   - Expected: complete Brainstorm's own accountable job using local methodology and references.
   - Falsifier: required invocation/load of Product Discovery, Decision Interview, Requirements, Domain Modeling, or any sibling.

6. **Conversation-only fast path**
   - Input: `Brainstorm this with me for ten minutes; don't create files.`
   - Expected: maintain coherent semantic state in conversation; no Markdown path, slug, changelog, file lifecycle, or finalization ceremony unless requested later.
   - Falsifier: file/template/persistence mechanics are mandatory.

7. **Project-native durable Markdown**
   - Input: project rules require one durable Markdown brainstorm artifact under an existing ideation convention.
   - Expected: load persistence mechanics, use project-native structure/location, maintain one current truth safely, and avoid parallel draft/final copies.
   - Falsifier: ignore project convention or create multiple current artifacts.

8. **Fixation pressure**
   - Input: user proposes `add an AI summary button`, but at least three materially different ways to solve the underlying progress need are plausible.
   - Expected: challenge the assumption that a summary button is inevitable; generate materially different behavior/boundary alternatives before deepening the first proposal.
   - Falsifier: only asks detailed questions about the original button.

9. **No fake alternatives under fixed truth**
   - Input: an authoritative policy fixes a key business rule.
   - Expected: keep the rule fixed and explore only genuinely open dimensions.
   - Falsifier: invent alternative policy values to satisfy a divergence ritual.

10. **Discriminate before converge**
    - Input: several possibilities survive; one fact, one hard constraint, and one owner trade-off distinguish them.
    - Expected: inspect the fact when possible, eliminate by the constraint, ask only the decision-changing owner judgment, and preserve remaining uncertainty.
    - Falsifier: generic pros/cons or confident recommendation without the discriminator.

11. **Async/stateful deepening**
    - Input: idea includes external callback, pending state, retries, and two actors.
    - Expected: load Semantic Lenses and reason about state/interruption/concurrency only because they are material.
    - Falsifier: omit recovery/state semantics or preload unrelated artifact lifecycle mechanics.

12. **Simple idea context economy**
    - Input: small reversible UI preference idea with one actor and no state/async/limits.
    - Expected: do not materialize deep state matrices, quota tables, OQ machinery, or workspace lifecycle without a decision need.
    - Falsifier: universal checklist ceremony.

13. **Re-entry after premise invalidation**
    - Input: a new observed fact invalidates the assumption supporting the leading possibility.
    - Expected: reopen affected frame/divergence/deepening only, preserve independent truth, and reconsider surviving alternatives.
    - Falsifier: keep the stale choice or restart every part indiscriminately.

14. **No forced finalization**
    - Input: user asks for a rough exploration checkpoint and wants to stop.
    - Expected: return `READY` or `PARTIAL` semantic state as appropriate without forcing L1/finalization/file materialization.
    - Falsifier: `Finalize / Continue / Hold` is mandatory for ordinary conversation.

## Skill-independence invariants

- Local references count as Brainstorm's own methodology; sibling Skills do not.
- A boundary handoff may remain unresolved when a downstream owner is unavailable without making Brainstorm's own completed work `BLOCKED`.
- Optional composition may improve evidence or downstream continuation, but absence of a sibling must not erase Brainstorm's exploration, correction, or completion method.
- Structural validation or a well-formed artifact is not behavioral proof.
