## 1. System Plane is the target, not ordinary SDLC judgment

- A Plugin has cross-capability truth, authority, evidence, and context rules duplicated across resident Plugin context and several Skills.
- The user asks to audit and upgrade the governing semantics themselves.
- Expected: `skill-plugin-engineering` owns the capability-engineering job and loads System Plane methodology only because the governing plane itself is the target; reconstruct the current plane and projections before proposing changes.
- Falsifier: treat the request as ordinary `sdlc` applicability/planning, or only edit one local Skill without reconstructing governing meaning.

## 2. Local method must not be promoted without pressure test

- A QA Skill contains a useful four-state verdict method.
- No other capability uses or needs that method.
- Expected: keep it Skill-local unless cross-capability evidence shows it is a governing semantic law.
- Falsifier: move it into the System Plane solely because it looks rigorous or reusable.

## 3. Atomic branch workflow survives delayed nested references

- Invoke the Skill on a request where the System Plane itself is explicitly the target. Load `SKILL.md`, then follow its direct conditional edge to `system-plane-method.md`; delay the deeper System Plane references.
- Expected: `SKILL.md` makes the branch load discoverable, and the loaded conditional method contains the full System Plane control path plus mandatory gate/re-entry/completion edges. `system-plane-model.md`, `system-plane-projection-contract.md`, and `system-plane-qualification.md` may deepen HOW only when their narrower conditions become material.
- Falsifier: `SKILL.md` does not expose the direct branch load when System Plane is the target, or a mandatory System Plane control edge is discoverable only by accidentally loading a deeper nested reference.

## 4. Projection preserves standalone Skills

- A revised evidence law must appear in a resident kernel and in an independently invokable implementation Skill.
- Expected: project the semantic meaning locally; do not require normal implementation work to invoke `skill-plugin-engineering` or load System Plane references.
- Falsifier: replace the local governing rule with a sibling/root pointer that breaks standalone execution.

## 5. No lifecycle router emerges from orchestration concerns

- The user wants stronger capability activation and context recovery.
- Expected: keep System Plane semantic laws separate from runtime orchestration mechanisms; do not encode Product -> Requirements -> Design -> Engineering -> QA as a mandatory route.
- Falsifier: create a phase graph, route table, or central harness as the System Plane revision.

## 6. Uncertainty x consequence remains a governing rigor primitive

- A proposed mutation has low semantic uncertainty but high blast radius.
- Expected: contain the change and strengthen proof/rollback discipline without pretending the semantics are unclear.
- A different mutation has high uncertainty and high consequence.
- Expected: stop the affected mutation until uncertainty or authority is resolved.
- Falsifier: use one fixed rigor level for both cases or treat the matrix as a lifecycle stage selector.

## 7. Conflict resolution is typed, not one precedence ladder

- User Acceptance has a current QA `FAIL`; the authorized business owner chooses `ACCEPTED_WITH_CONDITIONS` for a bounded business decision; a supporting Skill recommends release.
- Expected: preserve QA `FAIL`, preserve the authorized acceptance decision as a separate axis, keep User Acceptance as accountable owner of acceptance, and leave release authority with its actual owner. Resolve each relation in its own semantic dimension.
- Falsifier: treat "authority wins" as permission to rewrite QA to `PASS`, let System Plane replace the business decision, or let the supporting Skill silently take terminal ownership.

## 8. Law lifecycle removes stale governing truth without rewriting history

- A previously active System Plane rule is later shown to depend on one provider-specific mechanism and no longer passes cross-capability/mechanism-independent promotion tests.
- Expected: demote the rule to the proper local/runtime owner, migrate material projections, preserve historical evidence against the old exact revision, and remove the superseded active System Plane meaning after parity.
- Falsifier: keep the stale rule active as a silent fallback, delete old evidence, or call the change a wording clarification despite changed governing consequences.

## 9. Re-entry follows dependency reach

- A bounded plan has `A -> B -> C` and independently `A -> D`. Later evidence invalidates `B` while `A` remains valid.
- Expected: reopen `B` and dependent `C`; preserve `D`. If later `A` itself is invalidated, reopen every material descendant whose validity depends on `A`, potentially the whole outcome.
- Falsifier: restart `D` when only `B` changed, or keep `C` as completed after its premise `B` was invalidated.
