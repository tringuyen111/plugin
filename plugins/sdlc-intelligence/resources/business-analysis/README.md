# Business Analysis

Business Analysis defines observable behavior, rules, acceptance semantics, and
traceability from approved Product intent. It does not own priority, visual
design, technical architecture, implementation, or QA verdicts.

## User-invoked

- **[define-behavior](../../skills/define-behavior/SKILL.md)** — Turn approved Product intent into a traceable package of use cases, rules, stories, AC, NFRs, and downstream decisions.

## Model-invoked

- **[use-case](../../skills/use-case/SKILL.md)** — Define an actor goal through main, alternate, and error behavior without prescribing implementation.
- **[business-rule](../../skills/business-rule/SKILL.md)** — Define authoritative policy, validation, permission, calculation, or decision rules with sources and exceptions.
- **[user-story](../../skills/user-story/SKILL.md)** — Express one valuable actor capability linked to scope, use case, and rules without disguising technical tasks as stories.
- **[acceptance-criteria](../../skills/acceptance-criteria/SKILL.md)** — Define observable acceptance conditions, negative guarantees, and boundaries without prescribing implementation.
- **[traceability](../../skills/traceability/SKILL.md)** — Audit links and stale impact from outcome through release and documentation without becoming a second task tracker.
- **[non-functional-requirement](../../skills/non-functional-requirement/SKILL.md)** — Define measurable quality constraints and verification intent.
- **[uat-scenario](../../skills/uat-scenario/SKILL.md)** — Define traceable business-facing acceptance scenarios without choosing the UAT decision.
